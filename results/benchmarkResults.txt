Measurement methodology:
- The same input sizes were applied to all four complexity classes.
- 10 JVM warm-up executions were performed before measurement.
- 7 measured samples were collected for each configuration.
- The median execution time was retained.
- Batches of O(1) and O(log n) operations were executed to minimize timer overhead.
- A volatile result sink was employed to stop the JVM from eliminating unused computations.
- Execution times are reported in nanoseconds.

============================================================
GROWTH COMPARISON:


The measured results reveal four distinctly different growth patterns.

O(1):
The workload remains approximately constant as n increases.
Its execution time does not systematically depend on the input size.

O(log n):
Binary Search grows very slowly because the remaining search space is halved with each step.
approximately halved after every comparison.

O(n):
The linear workload increases approximately in proportion to the input.
This is because one operation is executed for each iteration.

O(n^2):
The nested-loop workload increases much more rapidly because the number of iterations grows exponentially.
The operations scale proportionally to the square of the input size.

============================================================
THEORETICAL COMPARISON:


The expected theoretical growth functions are:

O(1)     -> 1
O(log n) -> log2(n)
O(n)     -> n
O(n^2)   -> n^2

The empirical measurements follow the expected qualitative ordering:

O(1) < O(log n) < O(n) < O(n^2)

The precise execution times vary depending on the implementation, JVM, and hardware.
cache behaviour, operating-system scheduling and other constant
factors. Therefore, the individual nanosecond measurements should not
be interpreted as universal execution times.

The key finding is the growth pattern observed as n increases.
The experiment demonstrates that algorithms with higher asymptotic complexity perform less efficiently.
become increasingly expensive relative to algorithms with lower
complexity as the input size grows.
